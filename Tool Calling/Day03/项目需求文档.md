## 第一部分：项目需求文档——明确要实现什么

### 1.1 产品概述

**产品名称**：天气查询助手与 Tool Calling 运行轨迹面板。

当前已经有一个使用 Python 编写的命令行天气查询助手，能够查询一个或多个城市的天气和空气质量，并生成自然语言回答。

本次需求要增加一个浏览器页面。用户不再需要通过命令行提问，可以直接在页面中与天气助手连续对话；每次提交新问题时，页面右侧展示当前这一轮对话真实发生的模型请求和工具调用过程。

### 1.2 产品目标

1. 用户可以直接在网页中提出天气和空气质量问题；
2. 对话区域保留当前会话中的用户问题和助手回答；
3. 轨迹区域只展示当前一轮对话，不混入上一轮轨迹；
4. 用户能够查看本轮调用了哪些工具、传入什么参数以及返回什么结果；
5. 用户能够判断工具是串行还是并行调用；
6. 用户能够查看每个工具的调用时间、本轮总耗时和 Token 消耗量；
7. 查询失败或部分工具失败时，页面能够准确展示实际状态。

### 1.3 目标用户

- 使用网页查询城市天气和空气质量的普通用户；
- 希望观察 Tool Calling 完整过程的学习者；
- 需要演示连续调用和并行调用的教师；
- 需要排查工具选择、参数、耗时和 Token 使用情况的开发者。

### 1.4 页面布局

桌面端采用左右双栏布局：

```text
┌─────────────────────────────┬─────────────────────────────┐
│ 对话区域                      │ 本轮调用轨迹                  │
│                             │                             │
│ 用户：北京天气怎么样？           │ 总状态、总耗时、Token          │
│ 助手：北京当前……               │                             │
│                             │ 第1轮：search_city           │
│ 用户：再比较一下上海            │ 第2轮：weather + air_quality │
│ 助手：北京……上海……             │ 工具参数、结果、耗时、并发状态    │
│                             │                             │
│ [输入问题……          ][发送]   │                            │
└─────────────────────────────┴─────────────────────────────┘
```

- 左侧是对话区，显示当前会话的全部用户消息和助手回答；
- 右侧是轨迹区，只显示最近一次用户提问产生的调用轨迹；
- 手机端改为单列布局，先显示对话，再显示本轮轨迹；
- 对话内容较多时，用户仍能方便地回到最新消息和输入框。

### 1.5 核心使用流程

```plain
用户打开页面
→ 在对话框输入天气问题
→ 页面接受本轮问题并清空上一轮轨迹
→ 左侧显示用户问题和等待状态
→ 右侧显示本轮正在处理
→ 天气助手完成模型请求和工具调用
→ 左侧显示最终回答
→ 右侧显示本轮完整调用轨迹、总耗时和 Token 消耗
→ 用户继续提出下一个问题
→ 左侧保留对话历史，右侧重新清空并只展示新一轮轨迹
```

### 1.6 功能需求

#### 1.6.1 对话输入

- 页面提供问题输入框和发送按钮；
- 用户可以查询一个城市或多个城市的天气、空气质量以及两者对比；
- 输入为空或只有空格时不能发送，并显示明确提示；
- 用户可以使用键盘快捷操作发送问题；
- 查询执行期间不能重复提交同一问题；
- 查询执行期间应显示明显的处理中状态；
- 请求失败后输入内容不丢失，用户可以修改后重新发送。

#### 1.6.2 对话消息展示

- 左侧按照时间顺序展示当前会话的用户消息和助手回答；
- 用户消息和助手消息应有明确区分；
- 助手处理期间显示等待状态，完成后替换为真实回答；
- 助手失败时在对应消息位置显示可理解的错误信息；
- 用户提出“那上海呢”等后续问题时，助手能够结合当前会话继续回答；
- 新问题不会清除左侧已经完成的对话消息；
- 页面提供“清空对话”操作，执行前需要用户确认；
- 清空对话后，对话区域和右侧轨迹区域都恢复初始状态。

#### 1.6.3 本轮轨迹刷新规则

- 页面初次打开时，右侧显示“等待用户提问”；
- 用户提交一个有效的新问题后，立即清空上一轮调用轨迹；
- 清空上一轮轨迹不影响左侧对话历史；
- 当前问题处理期间，右侧显示本轮正在执行；
- 当前问题完成后，右侧只展示当前这一次提问产生的轨迹；
- 下一次提问开始时，再清空右侧内容并展示新一轮轨迹；
- 如果当前问题在执行前就因输入错误被拒绝，不清空上一轮已经完成的轨迹；
- 如果请求已经开始但最终失败，右侧展示本次失败轨迹，不能恢复上一轮轨迹。

#### 1.6.4 本轮轨迹概览

右侧顶部展示：

- 本轮用户问题；
- 本轮成功、失败、部分成功或处理中状态；
- 模型请求次数；
- 工具调用次数；
- 工具调用轮数；
- 串行、并行或混合调用方式；
- 本轮开始时间和结束时间；
- 本轮总耗时；
- 输入 Token、输出 Token 和总 Token；
- 本轮停止原因。

没有调用工具时，应明确显示“本轮未调用工具”，但仍然展示模型请求次数、总耗时和 Token 消耗。

#### 1.6.5 工具调用过程

- 调用轨迹按照真实执行轮次从上到下展示；
- 每一轮显示轮次编号、本轮调用数量和执行方式；
- 同一轮中多个互不依赖的工具同时调用时，显示“并行调用”；
- 同一轮只有一个工具时，显示“单工具调用”；
- 不同轮次之间应体现先后关系；
- 页面不能根据工具名称猜测并发，必须以本轮实际执行记录为准；
- 页面不能把并发工具排列顺序描述成真实完成顺序，除非轨迹中记录了实际时间。

#### 1.6.6 工具调用详情

每个工具调用至少展示：

- 工具名称；
- 工具用途说明；
- 调用编号；
- 所属轮次；
- 串行或并行状态；
- 调用参数；
- 工具返回结果；
- 成功或失败状态；
- 失败时的错误类型和错误信息；
- 工具开始时间；
- 工具结束时间；
- 工具调用耗时。

参数和返回结果默认可以折叠，用户展开后查看格式化内容。长内容不能破坏页面整体布局。

#### 1.6.7 时间统计规则

- 每个工具调用都应展示实际开始时间、结束时间和调用耗时；
- 时间应显示到毫秒级，较长耗时可以同时显示秒；
- 本轮总耗时从系统接受有效问题开始，到获得最终回答或确认失败为止；
- 本轮总耗时包括模型请求、工具执行、结果回传和最终回答生成；
- 并行调用时，本轮总耗时不能通过简单相加各工具耗时得到；
- 尚未完成的调用显示“执行中”，不能提前显示最终耗时；
- 如果某项时间没有被真实记录，页面显示“未记录”，不能使用推测值。

#### 1.6.8 Token 消耗统计

- 页面分别展示输入 Token、输出 Token 和总 Token；
- 一轮对话中发生多次模型请求时，Token 数量应按本轮所有模型请求累计；
- 工具函数和天气接口本身不计算模型 Token；
- Token 统计只包含当前这一轮对话，不与上一轮累计；
- 用户开始下一轮提问时，右侧 Token 统计随轨迹一起清空；
- 如果模型服务没有返回 Token 使用信息，页面显示“未返回”，不能显示为 `0`；
- Token 数据只能使用模型服务实际返回的结果，不能根据字符数自行估算后冒充真实值。

#### 1.6.9 失败与部分成功

- 模型请求失败时，左侧显示本轮失败回答，右侧显示失败阶段和已记录耗时；
- 某个工具失败时，只标记对应工具，其他成功结果继续保留；
- 同一轮中同时存在成功和失败工具时，整体状态显示“部分成功”；
- 达到最大工具轮次、工具调用数量限制或城市数量限制时，显示对应停止原因；
- 页面不能把未执行、超时、执行失败或缺少结果的工具显示为成功；
- 错误信息应便于理解，同时避免显示密钥和本机敏感路径。

#### 1.6.10 清空对话

- 页面提供“清空对话”按钮；
- 清空前需要用户确认，避免误操作；
- 确认后清除左侧对话记录和右侧本轮轨迹；
- 清空完成后显示新的空白会话；
- 取消清空时，当前对话和轨迹保持不变。

### 1.7 页面状态

| 页面状态 | 出现条件     | 对话区域           | 轨迹区域               |
| ---- | -------- | -------------- | ------------------ |
| 初始状态 | 尚未提问     | 显示欢迎语和输入框      | 显示等待用户提问           |
| 输入错误 | 输入无效     | 显示输入提示         | 保留上一轮轨迹            |
| 正在处理 | 有效问题已经提交 | 显示用户消息和等待状态    | 清空旧轨迹，显示本轮执行中      |
| 查询成功 | 获得最终回答   | 显示助手回答         | 显示本轮完整轨迹和统计        |
| 部分成功 | 部分工具失败   | 显示基于成功结果的回答或说明 | 分别显示成功与失败调用        |
| 查询失败 | 无法生成有效回答 | 显示失败信息         | 显示本轮停止位置、耗时和已获得的统计 |
| 清空完成 | 用户确认清空   | 恢复空白会话         | 恢复等待状态             |

### 1.8 使用体验要求

- 桌面端对话区与轨迹区能够同时查看；
- 手机端保持内容可读，不出现页面级横向滚动；
- 用户消息、助手消息、成功、失败、并行和处理中状态不能只通过颜色区分；
- 处理较慢时持续提供可见反馈，不能让用户误以为页面失效；
- 用户可以使用键盘完成输入、发送、展开详情和清空确认；
- 新回答出现后，对话区自动定位到最新消息；
- 轨迹较长时右侧可以独立滚动，不影响左侧输入；
- 参数和结果较长时，只在详情区域内部滚动；
- 页面不能重复显示同一次提交的回答或调用轨迹。

### 1.9 隐私与安全要求

- 页面和调用轨迹不得显示 API Key、密码和身份认证信息；
- 轨迹不展示完整系统提示词和未经处理的内部消息历史；
- 用户输入、助手回答、工具参数和工具结果只能作为普通文字展示；
- 错误信息不得包含本机敏感路径和完整异常堆栈；
- 用户提交问题后只能调用天气助手已经授权的工具；
- 页面不能提供任意网址访问、文件读取、系统命令和数据库操作能力；
- 清空对话不能影响天气数据源或删除项目文件。

### 1.10 本次需求不包含的功能

- 不提供用户注册、登录和多用户会话；
- 不提供云端对话同步和多人共享；
- 不支持上传文件、图片或语音提问；
- 不提供轨迹历史列表，右侧只展示当前一轮轨迹；
- 不统计跨会话、跨用户或整日累计 Token；
- 不展示没有真实记录的工具时间和 Token 数据；
- 不提供修改工具参数后重新执行的能力；
- 不提供医疗建议，也不把空气质量结果解释为医疗结论。

### 1.11 产品验收标准

| 验收场景 | 预期结果 |
| --- | --- |
| 查询北京天气 | 左侧显示真实回答，右侧显示本轮工具调用和统计 |
| 比较北京和上海 | 右侧按轮次展示多个城市相关调用，并标记实际并发调用 |
| 查询天气和空气质量 | 轨迹展示不同工具的名称、参数、结果和耗时 |
| 提出“那上海呢” | 左侧保留上下文并生成新回答，右侧只显示本轮新轨迹 |
| 连续提出第二个问题 | 提交成功后立即清空上一轮轨迹，不清空左侧对话 |
| 输入空内容 | 不发送请求，显示输入错误，上一轮轨迹保持不变 |
| 某个工具请求失败 | 失败工具被单独标记，其他成功结果继续显示 |
| 本轮包含多次模型请求 | Token 按本轮所有模型请求累计展示 |
| 模型没有返回 Token 信息 | 显示“未返回”，不显示为 `0` |
| 检查工具时间 | 每个工具显示真实开始、结束和耗时，缺失时显示“未记录” |
| 检查本轮总时间 | 显示从问题被接受到最终回答或失败的真实总耗时 |
| 点击清空对话并取消 | 对话和轨迹保持不变 |
| 点击清空对话并确认 | 左右区域均恢复初始状态 |
| 手机浏览器访问 | 页面单列可用，无页面级横向滚动 |

产品验收以用户实际看到的行为、状态和统计结果为准，所有时间与 Token 数据必须来自真实运行记录，不能由页面虚构。
