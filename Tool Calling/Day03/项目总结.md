# Day03 天气/空气质量/会议室助手 — 项目总结

> 基于实际代码（`main.py`、`model.py`、`service.py`、`tools.py`、`history.py`、`tracks.py`、`data/meeting_rooms.json`）整理，不含推测。

## 项目解决什么问题

一个**带工具调用（Tool Calling）闭环的命令行 AI 助手**：用户用自然语言提问，模型通过调用真实工具获取数据后作答，覆盖三类信息：

- **城市天气**（open-meteo 免费 API）
- **城市空气质量**（open-meteo 免费 API）
- **会议室信息**（本地 JSON 数据 `data/meeting_rooms.json`，共 6 间会议室）

核心工程问题：**让模型不凭记忆编造事实**——模型只负责决定"调用哪个工具、传什么参数"，数据一律来自工具的真实返回（`main.py:16` SYSTEM_PROMPT 明确要求"不得凭记忆生成坐标、天气、PM2.5、PM10、AQI 或会议室信息"）。同时处理了多轮工具调用的受控循环、并行调用、参数校验、历史持久化等问题。

## 整体流程

`main.py` 交互循环 → `service.py` 的 `UserService.run()` 受控循环（最多 10 轮模型调用）→ 模型返回 `tool_calls` → `run_tools()` 白名单查 `tools_map`、JSON 解析、Pydantic 校验、执行工具 → 结果回传给模型 → 模型给最终回答 → 存入历史/轨迹。

## 逐文件说明

### `main.py` — 交互入口

- **`SYSTEM_PROMPT`**（`main.py:6-24`）：给模型的行为规则。
  - 成功标准：先调 `get_city_pos` 拿真实坐标再查天气/空气质量；会议室先调 `get_room_info`；互不依赖的查询可同轮并行；最终回答只用工具结果并说明数据时间和单位。
  - 边界：不得编造数据；城市歧义时反问用户；最多处理 5 个城市，不访问用户提供的任意 URL（`main.py:19`）；工具失败如实说明；不给医疗建议。
- **`main()`**（`main.py:26-107`）：`asyncio` 入口。创建 `UserService` 和 `History`（读 `data/history.json`），拼出 `[system, *历史]` 消息列表，死循环读用户输入。
  - 每次调用 `service.run(messages, user)` 前用 `time.perf_counter()` 计时（`main.py:88-90`）。
  - 成功后把 user/assistant 两条消息追加进内存并 `history.save(messages[1:])`（去掉 system 存盘，`main.py:97-107`）；调用失败（返回 None）则不存历史（`main.py:92-94`）。
- **斜杠命令**（均在 `main()` 内）：
  - `/history`：打印历史轮数及截断到 120 字符的逐条消息（`main.py:39-54`）。
  - `/clear`：保留 system，清空内存和文件历史（`main.py:56-62`）。
  - `/rooms`：调 `load_meeting_rooms()` 打印全部会议室（名称/楼层/容量/地址/设备，`main.py:64-76`）。
  - `/help`：打印帮助（`main.py:78-86`）。

### `model.py` — 工具合同（给模型看的契约）

- **四个 Pydantic 参数模型**：
  - `CityPOS`（`city_name`，`model.py:5-7`）
  - `CityWeather`（`latitude`/`longitude`，`model.py:9-11`）
  - `CityQuality`（`latitude`/`longitude`，`model.py:14-16`）
  - `RoomInfo`（`room_name`，`model.py:19-21`）
  - 字段均有中文 `Field(description=...)`，生成 JSON Schema 时成为参数说明。
- **四个工具合同字典**：`city_tool`、`weather_tool`、`quality_tool`、`room_tool`（`model.py:25-63`），每个含 `type: "function"`、`name`（`get_city_pos` / `get_weather` / `get_quality` / `get_room_info`）、`description`、`strict: True`，参数来自 `model_json_schema()`。
- **`TOOLS`**（`model.py:66`）：四个合同的列表，是传给模型的工具声明。

> 合同与执行分离：合同名必须与 `tools.py` 里 `tools_map` 的键一致；模型侧只看到合同，执行侧只认注册表。

### `tools.py` — 工具实现与注册表

- **`get_city_pos(city_name)`**（`tools.py:12-28`）：aiohttp 调 open-meteo 地理编码接口，参数固定 `count=5&language=zh&countryCode=CN`（国家被硬编码为中国）。返回 `{"status": "success", "message": "查询成功", "data": res}`。`tools.py:19-23` 有一段被注释掉的非 200 状态检查。
- **`get_weather(latitude, longitude)`**（`tools.py:32-40`）：调 open-meteo forecast，`current` 取温度/相对湿度/风速，`hourly` 取温度。
- **`get_quality(latitude, longitude)`**（`tools.py:44-52`）：调 open-meteo air-quality，`current` 取 `european_aqi, pm10, pm2_5, nitrogen_dioxide, ozone`，`timezone=Asia/Shanghai`。
- **`load_meeting_rooms()`**（`tools.py:56-61`）：读 `data/meeting_rooms.json`，`JSONDecodeError`/`OSError` 或非列表时容错返回 `[]`。
- **`get_room_info(room_name)`**（`tools.py:65-95`）：先按 `name` 精确匹配（`tools.py:75-81`）；不中再按"名称包含输入"模糊匹配，命中多个则整个 `matched` 列表返回（`tools.py:83-89`）；都找不到返回 `status: "error"` 且 message 提示确认名称（`tools.py:91-95`）。
- **`tools_map`**（`tools.py:99-116`）：执行侧注册表，名字 → `{"function": 函数, "args": Pydantic 模型}`，四对映射。

> `tools.py:1` 导入了 `requests` 但全文件未使用（遗留导入）。

### `service.py` — 受控循环核心

- **模块级环境配置**（`service.py:14-24`）：`load_dotenv()` 读 `.env` 的 `OPENAI_API_KEY` / `OPENAI_MODEL` / `BASE_URL`，缺任一直接 `raise RuntimeError`。
- **`trim(messages, max_rounds)`**（`service.py:28-40`）：裁剪历史。`max_rounds` 为负抛 `ValueError`；`max_rounds == 0` 只保留 system；否则保留 `system.copy()` + 最后 `max_rounds * 2` 条（每轮 user+assistant 两条）。
- **`UserService.__init__`**（`service.py:44-50`）：建 `OpenAI` 客户端，并创建 `Tracks("data/tracks.json")`。
- **`send(messages)`**（`service.py:53-63`）：同步调用 `chat.completions.create`，`tools=TOOLS`、`tool_choice="auto"`、`parallel_tool_calls=True`（允许同轮多个工具调用）。
- **`run(messages, user_messages)`**（`service.py:66-123`）：一次完整工具闭环。
  1. 先 `trim(..., max_rounds=5)` 裁剪传入消息，记录 `start_index` 后追加 user 消息。
  2. `for i in range(10)` 最多 10 轮：模型调用异常则打印并返回 `None`（`service.py:82-87`）。
  3. 有 `tool_calls` 时：先把 assistant 消息 `model_dump(exclude_none=True)` 并强制补 `content=""` 追加进消息（`service.py:92-98`）——保证消息顺序：assistant 在前、tool 结果在后。
  4. 用 `asyncio.gather(..., return_exceptions=True)` **并发**执行所有工具（`service.py:100-103`），每个 tool 结果按 `tool_call_id`（复用模型返回的原始 id）追加 `role="tool"` 消息；任何工具抛出的异常统一转成 `{"ok": False, "error": "tool_failed"}` 回传（`service.py:105-106`）。
  5. 无 `tool_calls` 时视为最终回答：追加 assistant 消息、把 `messages[start_index:]`（本轮完整轨迹）连同 12 位随机 id 存入 `Tracks`，返回 `message.content`（`service.py:113-121`）。
  6. 循环耗尽则 `raise RuntimeError("达到最大轮数，未得到最终回答")`（`service.py:123`）。
- **`run_tools(tool)`**（`service.py:126-154`）：单个工具的安全执行链。
  1. 打印 tool id/名称/参数。
  2. `tools_map.get(...)` 白名单查询，查不到抛 `RuntimeError("访问的工具不存在！")`（`service.py:132-134`）。
  3. `json.loads` 解析模型参数（禁 eval，失败抛异常，`service.py:137-140`）。
  4. Pydantic `model_validate` 校验（`service.py:143-146`）。
  5. `await curr_tool["function"](**args.model_dump())` 执行（`service.py:149-153`）。

> 与根目录 CLAUDE.md 描述略有出入的实际行为：解析失败、校验失败、执行失败在 `run_tools` 中都只是 `raise RuntimeError`，最终在 `run()` 的 gather 处**统一**变成 `{"ok": False, "error": "tool_failed"}`——实际只有 `tool_failed` 一种错误码回传给模型（工具自身返回的 `status: "error"` 如会议室未找到则是另一条通道）。

### `history.py` — 会话历史持久化

- **`History.__init__(history_path)`**（`history.py:5-9`）：转成 `Path`、`mkdir(parents=True, exist_ok=True)` 建父目录、`load()` 载入 `self.messages`。
- **`load()`**（`history.py:11-24`）：文件不存在返回 `[]`；解析失败容错返回 `[]`；**过滤掉 `role == "assistant"` 且 content 为空的字典**——防止历史上只含 `tool_calls` 而 content 为空的 assistant 消息被再次发给模型（因为对应的 tool 结果没存进历史）。
- **`save(messages)`**（`history.py:26-30`）：`json.dumps(..., ensure_ascii=False, indent=4)` 写入，保证中文可读。

### `tracks.py` — 调用轨迹持久化

- **`Tracks.__init__(path)`**（`tracks.py:7-10`）：建父目录。
- **`load()`**（`tracks.py:12-20`）：容错读 JSON 列表，失败或非列表返回 `[]`。
- **`save(track)`**（`tracks.py:23-29`）：`load()` 出旧列表 → `append(track)` → 整体写回。**追加式**存储：`data/tracks.json` 中每个元素是一条 `{"id": ..., "tracks": [本轮完整消息轨迹]}`，用于事后复盘模型每次调用了哪些工具、传了什么参数。

### `data/meeting_rooms.json`

6 间会议室（星辰/望岳/云帆/听雨/凌云/听涛），字段：`name`、`address`、`floor`、`capacity`（6–50 人）、`equipment` 列表。是 `get_room_info` 的数据源，也是 `/rooms` 命令展示的内容。

## 值得注意的细节

1. **`tools.py:1` 的 `import requests` 是死导入**，整个文件只用 aiohttp。
2. **`tools.py:19-23` 状态码检查被注释掉**，HTTP 非 200 时不会按注释所示返回 error，而会走 aiohttp 自身的异常路径。
3. **`service.py:99` 注释编号跳过了 "3."**（只有 1、2、4），纯注释瑕疵。
4. `get_city_pos` 把 `countryCode=CN` 写死，模型侧无论用户问哪个国家，地理编码都限定在中国。
5. `main.py` 的 `messages` 里 system 一直存在，但持久化（`history.save(messages[1:])`）和 `trim()` 都刻意把它排除在对话体之外，下次启动再由 `main()` 重新拼回。
